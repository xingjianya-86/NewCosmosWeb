> 口径权威：桌面 `docs/20261112_重病判定双口径与AI管线.md`（本文不复述口径，只写 Web 侧**差异与接线事实**）。

## 一、与桌面的差异（只列不同点）

| 维度 | 桌面（NewCosmosCode） | Web（本仓库） | 说明 |
|---|---|---|---|
| 判定入口 | ViewModel 内直接注入 `ISevereDiseaseAdviceService`（进程内三级管线） | 前端 → `POST /api/ai/severity*` → Server 端点 → 同一个 Core 服务 | Web 多一层 HTTP；管线与闸门仍在 Core，Server 只做权限/组包/错误映射 |
| 服务地址 | `config/network.ini` 的 `OcrServiceUrl`（`IConfigService`） | 环境变量 `NC_OCR_SERVICE_URL` → `ServerEnvironmentOptions.OcrServiceUrl` → `ServerConfigService.GetNetworkOptions()` | **同一份 `NetworkOptions.OcrServiceUrl`**，AI 与 OCR 同服务同地址；留空=未启用 |
| 消抖 | 确定性命中同步秒出；LLM 路径 600ms 消抖 | 由 ICD-10 `@change` 触发（失焦/回车），无 600ms 消抖 | Web 输入本身按 change 提交，天然已是“最后一次”；确定性层同样在服务端先走，毫秒级返回 |
| 否决态存放 | 申请人 `_severeDiseaseAutoCheckRejected`；成员 `FamilyMember.AiSevereDiseaseRejected`（落库） | 申请人 `ref`；成员/赡养人组件内 `WeakSet<object>`（**不落库**，仅本会话） | Web 尚无该列，按会话内否决处理；语义一致（否决后本会话不再自动勾） |
| 建议条 | 桌面单根 UI 条（`AiSeveritySuggestionText` / 成员 `AiSuggestionText`） | `el-alert`（closable），Step1 一条、Step2 成员卡与赡养卡各一条 | `@close` 只隐藏、不动勾选 |
| 加载恢复抑制 | `_suppressSevereRejectTrack` 抑制加载期 true→false | 不需要：Web 用 `@change`（Element Plus 仅用户点击触发，程序化赋值不触发） | 见 §3 |
| 失败降级 | `Result.Failure` 显式上抛 → 显示“无建议” | 前端 `catch` 后**静默**：不弹 `ElMessage`、不阻断保存 | 对齐“失败=无建议”§7 降级口径 |

## 二、端点契约（新增）

权限：`[INCOME_VIEW, TEMP_VIEW]` 任一命中（与 `Icd10Endpoints` 完全一致）。
判定请求不含 `applicationId`，**不做数据范围校验**。

### `POST /api/ai/severity`

请求 `{ name?, code, userRejected }`；`name` 为空时由 ICD-10 字典按 `code` 兜底带名，
仍带不出名 → **400 `VALIDATION_ERROR`**。

响应 `{ verdict, matchedItem, confidence, reason, source, policyVersion, model, autoEligible, autoChecked, suggestion }`

- `autoChecked` = Core `ISevereDiseaseAdviceService.ShouldAutoCheck(judgment, userRejected)`；
- `suggestion` = `AiJudgeConstants.FormatSuggestion(judgment, autoChecked)`，
  **仅 `verdict==='severe'` 时非空**（与桌面 `ApplyApplicantJudgment` 同口径，非 severe 不出建议条）。

### `POST /api/ai/severity/cost`

请求 `{ selfPaid12m, isRural, userRejected }`（`isRural = hukouType !== 'Urban'`）。

响应 `{ severe, threshold, autoChecked, suggestion }`

- 阈值经 `GetCostThresholdAsync` 单点读取；**threshold≤0（未配置/无效）→ `severe=false, suggestion=""` 静默降级，不报错**、不硬编码回退值；
- `severe` = `SevereDiseaseByCostRule.IsSevereByCost`（严格大于）；
- `suggestion` = `SevereDiseaseByCostRule.FormatSuggestion`。

### 错误映射（`ApiErrors.Map` 无 AI_* 条目，端点自带）

| 错误码 | 状态码 |
|---|---|
| `AI_SERVICE_UNREACHABLE`（未配置地址/连不上） | 503 |
| `AI_TIMEOUT` | 504 |
| `AI_JUDGE_FAILED` | 502 |
| `CANCELLED` | 408 |
| 其它（DB/配置类） | 回落 `ApiErrors.FromResult` 通用映射 |

## 三、前端接线点

| 文件 | 改动 |
|---|---|
| `web/src/api/aiJudge.ts`（新增） | `judgeSeverity` / `judgeSeverityByCost`，**per-request `timeout: 110_000`**（默认 20s 会掐断 LLM 路径） |
| `web/src/views/applications/form/Step1Basic.vue` | ① `handleDiseaseCodeChange` 拿到 name 后触发判定；② **删除 `watch(diseaseCode)` 自动勾选**（绕过 ShouldAutoCheck 的最大语义 bug）；③ 重病勾选 `@change`，`false → applicantRejected=true`；④ 自付字段 `@change` 触发费用判定；⑤ `el-alert` 建议条 |
| `web/src/views/applications/form/Step2Members.vue` | 成员卡 + 赠养卡同构两套：`WeakSet` 否决态、`reactive(new Map())` 行级建议文案（不落库）、勾选 `@change`、自付 `@change`、各一条 `el-alert` |

统一语义：

- **只勾不取消**：`autoChecked && !isSevereDisease` 才置 `true`，AI/规则永不改为 `false`；
- **人工优先**：用户取消一次即否决，本会话不再自动勾（建议条仍可显示供参考）；
- **竞态丢弃**：响应回来时再读一次编码与否决态，与发送时不一致即丢弃过期响应；
- **只读模式**（`isLocked` / `isReadonly`）不触发、不展示。

## 五、验证

- `dotnet build NewCosmosWeb.slnx` ✅
- `dotnet test tests\NewCosmos.Core.Tests\NewCosmos.Core.Tests.csproj` ✅（含恢复的真实清单用例）
- `cd web; npm run build` ✅（`vue-tsc --noEmit` + `vite build`）

代码走查冒烟（无需起服务）：

1. 清单内编码（如 N18.5 / C80.9）→ ICD-10 带出名 → 确定性层秒回 `source=deterministic` → 建议条 + 自动勾；
2. 目录外编码（如 J06.9）→ `verdict≠severe` → 无建议、不勾选；
3. **手动取消后再改码 → 不再自动勾**（`userRejected=true` 过闸门，`autoChecked=false`，只出建议）；
4. 成员卡 / 赠养卡同 1–3（按行对象的 `WeakSet` 互不串扰）；
5. 自付超阈值（农村 29381 / 城镇 41757 档）失焦 → 自动勾 + 费用口径建议条；
6. 断网 / 未配置 `NC_OCR_SERVICE_URL` → 端点 503（或前端超时），**前端静默、无建议、保存正常**。
