# 动态管理：历史导入库双源检索与建档（2026-11-27）

## 背景

桌面版（NewCosmosCode）的"保障对象动态管理/变更页"搜索档案时是**双源合并**：
当前库 `nc_biz_applications` + 6 个历史导入库（农村低保 / 城市低保 / 低保边缘 /
特困供养 / 刚性支出 / 其他困难）。导入库记录显示"待建档"，点击变更时
自动调 `MigrateToCurrentAsync` 建档迁移进当前库再办理。

Web 版此前只查当前库且仅 `Approved/Completed`，导致只在导入库中的人员
（如历史在保对象）在此页完全查不到，与桌面版体验不一致。

## 本次补法（方案 A：对齐桌面）

### 服务端

| 端点 | 权限 | 说明 |
|---|---|---|
| `GET /api/social-assistance/change-management/imported-search?keyword=` | `CHANGE_VIEW` | 复用 Core `IImportedArchiveService.SearchAsync`（6 库 × 家庭直查 + 成员回查，总体 LIMIT 20）；身份证脱敏；按来源表+行号批量补出 `existingApplicationId`（已建档角标）。与「档案查询」一致不做数据范围过滤 |
| `POST /api/social-assistance/change-management/imported/{sourceTable}/{sourceId}/migrate` | `CHANGE_MANAGE` | 来源表白名单（6 表）→ 读取导入库家庭详情 → **数据范围校验**（把导入库乡镇/村文本套用与列表完全相同的 `DataScopeTarget.Applications` 条件，`1=0`/SELF 均拒绝）→ 调 Core `MigrateToCurrentAsync`（幂等，已建档直接返回既有 ID） |

实现位置：
- `src/NewCosmos.Server/Services/ChangeManagementQueryService.cs`
  （`SearchImportedAsync` / `IsImportedRecordInScopeAsync` / `LoadExistingApplicationIdsAsync`）
- `src/NewCosmos.Server/Endpoints/ChangeManagementEndpoints.cs`
  （`SearchImportedAsync` / `MigrateImportedAsync` + 来源表白名单）
- 契约：`src/NewCosmos.Server/Contracts/ChangeManagementContracts.cs`
  （`ImportedArchiveItemDto` / `ImportedArchiveSearchResponse` /
  `MigrateImportedArchiveRequest` / `MigrateImportedArchiveResponse`）

### 前端

`web/src/views/social-assistance/change/ChangeManagementView.vue`：

- 关键词搜索时并行调用当前库列表 + 导入库检索；
- 搜到导入库记录时，在列表下方展示「历史导入库（待建档）」卡片：
  姓名（含成员命中说明）/ 脱敏身份证 / 来源+推导分类 / 地址 / 人数 / 保障金 /
  建档状态 / 操作；
- 未建档 → 「建档并办理」：建档成功（草稿）后跳转五步表单补全，
  补全并办结后即出现在"在享对象"列表；
- 已建档 → 「查看档案」：直接加载当前库详情（无需再建档）；
- 导入库无命中时给出兜底文案（提示核对"数据中心 → 数据导入"批次）。

## 口径说明

- 导入库检索**不做**数据范围过滤（与「档案查询」一致，均只做权限校验）；
  真正的越权拦截在建档写入时执行——`IsImportedRecordInScopeAsync` 用
  `probe` 子查询复用 `DataScopeFilterBuilder` 的 SQL，避免重写区域匹配规则。
- 建档后的档案为 `Draft`（`current_step=1`），不进入"在享对象"列表；
  需在五步表单补全提交后才成为在享对象（与桌面版"补全模式"一致）。
- 幂等：同一 `source_table + source_id` 只允许建档一次，重复点击返回
  `AlreadyExisted=true` 与既有 `applicationId`。
- 金额/分类/成员迁移全部由 Core 决定，Server 不重算。

## 验证

- `dotnet build NewCosmosWeb.slnx`
- `dotnet test tests\NewCosmos.Core.Tests\NewCosmos.Core.Tests.csproj`
- `cd web; npm run build`
- 手工冒烟：动态管理搜"李文财" → 若仅导入库有记录，卡片显示"待建档" →
  点「建档并办理」→ 跳转五步表单 → 保存后档案状态为草稿；再次搜索同人显示
  "已建档"并可「查看档案」。
